InstaServe / istaseva — System Architecture

Modular monolith on AWS (ap-south-1). Web + Mobile clients → Express API on ECS Fargate → Postgres / Redis / DynamoDB / OpenSearch / S3, with Razorpay, Firebase, Gemini, and SES/SNS integrations.

  participant P as Postgres

  participant N as SNS→SQS→SES/SMS

  C->>A: POST /api/bookings
  A->>R: SETNX lock:slot (TTL 5m)
  A->>P: BEGIN · check overlaps · INSERT booking · COMMIT
  A-->>C: { bookingId }
  C->>A: POST /api/payments/create
  A->>Z: orders.create
  A-->>C: { orderId }
  C->>Z: Razorpay Checkout (pay)
  Z-->>A: webhook (signed)
  C->>A: POST /api/payments/verify
  A->>P: BEGIN · payment=paid · booking=confirmed · guarantee · COMMIT
  A->>R: DEL lock:slot
  A-)N: publish booking.confirmed
  A-->>C: { success }

How to read this

Traffic path. Browser/app → CloudFront → (SPA assets or /api/* to ALB) → ECS Fargate running the Express monolith.
State. Postgres is the transactional source of truth; Redis provides distributed slot locks (prevents double-booking) and caching; DynamoDB stores append-only event streams; OpenSearch powers search; S3 holds user uploads and KYC docs.
Async. Booking events fan out via SNS → SQS (with DLQ) → SES / SNS-SMS so the API never blocks on delivery.
External. Firebase for auth (Cognito is swappable), Razorpay for payments with signed webhooks, Gemini 2.5 for AI onboarding (OpenAI/Anthropic configurable as fallback), Google Cloud TTS for speech, Mixpanel optional. DigiLocker KYC is wired but not yet integrated.
Secrets. Every credential (DB, JWT, Firebase admin, Razorpay, Gemini) is pulled from AWS Secrets Manager at boot — nothing lives in the image.
